Git и GitHub
без путаницы

Git — это система контроля версий. GitHub — сервис, где такие проекты хранятся и где над ними работают вместе. Разберёмся, из чего состоит рабочий процесс — от первого коммита до слияния изменений.

Начать разбор → Открыть github.com

типичный цикл: своя ветка → изменения → pull request → слияние в main

@@ раздел — базовые понятия @@

Пять слов, на которых всё держится

Остальное — надстройки над этими понятиями.

repository

Репозиторий

Папка проекта, за историей изменений которой следит Git. В ней хранится не только текущий код, но и все прошлые версии.

commit

Коммит

Сохранённый снимок изменений с сообщением о том, что и зачем поменялось. Из коммитов складывается история проекта.

branch

Ветка

Отдельная линия разработки. Позволяет пробовать изменения, не трогая основной код в ветке main, пока результат не готов.

pull request

Pull request

Предложение влить изменения из одной ветки в другую. Место, где обсуждают код и просят его проверить перед слиянием.

clone

Клонирование

Копирование репозитория с GitHub на свой компьютер вместе со всей историей — чтобы работать с ним локально.

fork

Форк

Своя копия чужого репозитория на GitHub. Способ предложить изменения в проект, к которому нет прямого доступа.

@@ раздел — команды @@

Минимальный набор команд

Этого достаточно, чтобы пройти путь от пустой папки до первого pull request.

терминал
# начать отслеживать папку как репозиторий
git init

# скачать существующий репозиторий с GitHub
git clone https://github.com/имя/проект.git

# отметить файлы, которые войдут в коммит
git add .

# сохранить снимок изменений с сообщением
git commit -m "описание изменений"

# создать новую ветку и переключиться на неё
git checkout -b имя-ветки

# отправить коммиты на GitHub
git push origin имя-ветки

# забрать изменения, которые появились на GitHub
git pull

@@ раздел — первые шаги @@

С чего начать сегодня

1

Завести аккаунт на github.com

Понадобится только имя пользователя и почта. Аккаунт бесплатный.

2

Установить Git на компьютер

Проверить, установлен ли он уже, можно командой git --version в терминале.

3

Создать первый репозиторий

На GitHub нажать «New repository» — или выполнить git init в папке с проектом локально.

4

Сделать первый коммит

Изменить файл, затем git add и git commit с понятным описанием того, что сделано.

5

Отправить изменения на GitHub

git push — и репозиторий на GitHub обновится тем, что сохранено локально.

6

Открыть pull request

Если изменения делались в отдельной ветке — предложить влить их в main прямо на GitHub.
